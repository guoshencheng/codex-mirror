# 额度历史与折线图设计

日期：2026-09-29

状态：用户已于 2026-09-29 审阅通过，进入实施计划阶段；尚未实现产品代码。

## 目标与已确认需求

额度数据持续存入数据库，用户可在现有额度详情中查看历史折线图。用户已明确历史保留最近 **90 天**。

成功标准：关闭页面后仍由 worker 采集；已有数据库历史可直接查看；按账号切换时间范围；正确呈现额度重置、数据缺失与采集停止。以下展示与查询细节作为实施计划依据。

## 现状

- `src/server/quota/refresh.ts` 每次成功刷新，在同一事务内更新 `quota_latest` 并追加 `quota_snapshots`。正常刷新间隔为 300 秒加 0～30 秒抖动。
- `src/server/read-model/handlers.ts` 的托管账号手动刷新，以及 `src/server/providers/codex/login-repository.ts` 的首次登录成功路径，也会追加历史。
- `src/worker/main.ts` 每天清理一次 90 天前的历史，启动后第一次清理在 24 小时后。清理由 worker 存活及数据库可用性决定，并非到期立即物理删除。
- `migrations/001-quota.sql` 已有历史表及按时间清理的索引，但没有按账号查询历史的复合索引。
- `src/components/dashboard.tsx` 点击额度行后展示 `QuotaCard`。主站与 `display/` 独立展示端共用这些组件；历史尚无查询接口。

## 方案选择

采用复用现有快照表、增加查询接口及图表的方式。已有数据无需回填，数据库保留原始快照，查询时生成适合图表的序列。

不选择另外建一张指标采样表：会引入重复写入与迁移，对目前 90 天查询没有必要。不选择独立时序数据库：增加部署与维护成本。正常轮询下每账号 90 天约 2.4～2.6 万条快照，手动刷新会增加记录；这是条数估算，不是空间承诺。

## 数据记录与保留

- 保留原有成功采集追加记录的行为；即使额度未变也记录，便于区别稳定值和采集停止。
- 失败只更新现有刷新状态，不写虚假的 0 值或复制上次成功值。历史图表达的是成功采集结果，无法还原每一次历史失败原因。
- 保留现有每日清理策略与 90 天阈值；查询独立限制最近 90 天，即使 worker 停机造成清理延迟，也不展示更早数据。
- 不改 `quota_latest` 的保留行为。即使历史清理后最新值仍存在，也只作为当前额度展示，不回填为新的历史点。
- 新增迁移 `migrations/010-quota-history-index.sql`，建立 `(account_id, observed_at, id)` 复合索引，保留原有时间清理索引。
- 沿用账号删除时级联删除历史的行为；账号停用后不提供历史查询。无凭据或令牌写入历史接口响应。

## 查询与序列

新增主站 `GET /api/provider-accounts/[id]/history?range=24h`，以及展示端 `GET /api/display/provider-accounts/[id]/history?range=24h`。

- `range` 仅允许 `24h`、`7d`、`30d`、`90d`，默认 `24h`；不开放任意 SQL、粒度或无限时间查询。
- 主站沿用 `requireAdmin` 会话鉴权；展示端沿用现有 Bearer Token、来源白名单和 OPTIONS 预检规则。共享查询服务，避免两个接口返回不同口径。
- 返回 `accountId`、`range`、`from`、`to`、`generatedAt`、`retentionDays: 90`、`bucketSeconds` 和 `series`。时间为 UTC ISO 字符串，范围为 `[from, to]`，以服务器时间计算。
- 每条序列包含稳定标识、名称、类型、单位和点列表。额度窗口按 `kind + key + windowDurationSeconds` 区分；余额按 `kind + key + currency` 区分。窗口长度或币种变化时拆开，普通额度重置不拆序列。
- 点保留真实 `observedAt`、值、额度窗口 `resetsAt` 和是否应与前一点断开。余额保留原始十进制字符串，绘图转换不能覆盖原值。
- 使用 `observed_at ASC, id ASC` 稳定排序；同账号同时间戳取最大 id 的快照，防止重叠点产生歧义。
- 时间桶分别为 5 分钟、30 分钟、2 小时、6 小时。每条序列每桶保留首点、末点、最小值点、最大值点，去重后按原时间排序；不取均值，避免抹平额度耗尽和重置。最多 361 个桶，每条序列最多 1444 个实际采样点。
- 先识别缺失再降采样。指标缺失、值为空、服务明确不可用，或相邻有效采样间隔超过 15 分钟，均形成断点。若被省略的采样之间存在断点，保留点之间仍须断开，不用聚合后的时间距离猜测。
- 降采样只影响响应，不改数据库原始数据。长范围图标注为采样趋势，可能省略同一桶中的部分细节。
- 当前账号存在但无历史返回 200 和空序列；非法范围返回 400；未登录或 Token 无效返回 401；非法账号、停用账号或不存在账号返回 404；来源不允许返回 403；数据库不可用返回 503。所有响应设置 `Cache-Control: private, no-store`。

## 额度详情交互

- 在现有额度详情当前指标下增加“额度历史”，默认最近 24 小时，提供 24 小时、7 天、30 天、90 天切换；不在首页每张额度行直接绘制图表。
- 百分比图以“剩余额度”为口径，`100 - usedPercent`，纵轴固定 0～100%。5 小时与周窗口分别画线，用图例区分；保留实际重置跳变，不使用平滑曲线。
- 余额用独立图表并显示币种，币种不同必须分图，避免与百分比共用纵轴。
- 使用 React 与 SVG 实现折线、坐标轴、图例和提示，不新增图表依赖。横轴按真实时间比例，提示支持鼠标、触摸和键盘，显示本地采集时间、序列名称、精确值以及可用的重置时间。
- 一条有效记录显示单点；没有记录显示“所选时间范围内暂无额度历史”；不足完整时间范围时仅绘制真实数据。图表不外推到当前时间。
- 加载和失败状态仅影响历史区域，保留当前额度卡；失败提供重试入口。重新加载失败时保留同账号同范围旧图，并标注更新失败。
- 仅打开额度详情时请求；切换账号或范围立即取消旧请求并防止迟到响应覆盖新内容。详情打开且页面可见时，每 60 秒重取；关闭详情、卸载或页面隐藏后停止，恢复可见时重取。
- 历史读取通过独立加载函数注入共享组件：主站使用同源请求，展示端使用配置的 API 地址和 Token；不要将只读状态误当成没有历史读取权限。静态 demo 不发真实历史请求，使用本地示例或显示无历史能力。
- 适配现有 400×400 缩放面板，图表位于详情滚动容器内；范围按钮可换行，避免横向溢出。提供文字摘要辅助读取。

## 验证与验收

1. 数据库集成验证：成功刷新追加历史且最新值更新；失败不追加；清理仅删除阈值之前的历史、保留边界记录且不删除最新值；按账号隔离，时间范围和同时间戳排序正确。
2. 序列单元验证：90 天边界、空指标、单点、指标消失再出现、窗口长度变化、不同币种、十进制原值、重置尖峰、长时间无采样及降采样前后断点一致。
3. 接口验证：两类鉴权、跨域允许与拒绝、OPTIONS、非法范围、账号不存在、无历史和数据库失败；确保不返回凭据且不公开缓存。
4. 组件验证：默认范围、切换、请求竞态与取消、60 秒刷新和可见性、加载失败及重试、空态、图例与点提示。
5. 浏览器验证：主站及独立展示端打开账号、切换范围、返回面板；确认小尺寸布局、触摸与键盘可用，关闭详情后不再请求历史。
6. 实现后执行相关单元与集成测试、`npm run typecheck`、主站构建与 `npm run display:build`；数据库或浏览器依赖不可用时明确记录未验证项。
